# PersonalOS V1

> 目的：把“每天忙很多但推进很少”改造成“每天都有明确交付”。
>
> 版本：V1.0（先运行 14 天，再决定是否开发 UI、数据库或更复杂自动化）

## 1. PersonalOS 解决什么

PersonalOS 不是任务管理软件，而是一套个人执行系统。

它把四件事分开：

1. **方向层：7 天冲刺** —— 这一阶段到底要把什么做成。
2. **项目层：GTD Lite** —— 脑子里所有事情有地方放，不靠记忆，也不因为“突然想到”就立刻去做。
3. **今日层：每日 3 个成果** —— 今天到底什么算完成。
4. **执行层：AI / Hermes** —— 帮忙排序、提醒、复盘和维护状态，但不替人决定人生方向。

核心原则：

> 想到 ≠ 现在做。
>
> 研究 ≠ 完成。
>
> 忙碌 ≠ 推进。
>
> 每天先交付 A，再允许扩张。

## 3. 每天怎么用

### 早上 / 开工前：10 分钟

按顺序只看：

1. `01_CURRENT_FOCUS.md`
2. `03_NEXT.md`
3. 昨天的 daily log
4. `00_INBOX.md`（只做归类，不顺手执行）

然后创建当天 daily 文件，只写 3 个成果：

- **A：今天最重要的可见成果**
- **B：推进主线的第二成果**
- **C：收尾 / 记录 / 复盘成果**

若 A 没完成，原则上不增加新任务。

### 白天

突然想到任何新东西：只写进 `00_INBOX.md`。

不要因为“可能有用”立即开网页、搜工具、开新仓库、重做系统。

### 晚上 / 收工：10 分钟

只回答：

1. A/B/C 完成了什么？
2. 今天最大的阻塞是什么？
3. 哪些时间花掉了却没有推进本周目标？
4. 明天第一件事是什么？

未完成事项不能默认滚入明天，必须重新判断：继续 / 拆小 / 排队 / 放弃。

## 4. 每周怎么用

每 7 天做一次 Weekly Review：

1. 清空 Inbox；
2. 检查 Projects 是否还值得做；
3. 检查每个 Active Project 是否有明确 Next Action；
4. 处理 Waiting；
5. 浏览 Someday，但不因兴奋立刻启动；
6. 回看 7 天实际成果；
7. 选出下一个 7 天唯一主结果。

一周最多 **1 个主战场**。

其他事情可以维护，但不能和主战场争夺深度时间。

## 5. AI / Hermes 的角色

AI / Hermes 是 **参谋长 + 执行秘书**，不是老板。

它可以：

- 读取当前状态；
- 根据 7 天目标提出当天 A/B/C；
- 主动删减任务；
- 检查是否跑偏；
- 帮忙把任务拆成下一步动作；
- 晚间做复盘；
- 每周整理 Inbox / Projects / Waiting / Someday；
- 发现重复、稳定、耗时动作后，提出自动化候选。

它不可以：

- 因为发现新机会就自动替换主项目；
- 因为某个工具很酷就建议立刻搭系统；
- 在 A 未完成时不断添加“顺便做”的任务；
- 把阅读、搜索、研究自动计为业务成果；
- 把未经验证的方法直接固化成 Skill / Workflow；
- 替用户做不可逆的重大方向决定。

## 6. 14 天试运行规则

前 14 天禁止为 PersonalOS 开发：

- 新 UI；
- 数据库；
- 手机 App；
- Dashboard；
- 复杂标签系统；
- 多 Agent 编排；
- 自动同步一切。

先证明：

> 这套文件能不能让每天的可见成果明显增加。

只有一个动作实际重复发生多次、稳定、耗时，才进入自动化候选。
