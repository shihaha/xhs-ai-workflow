# Weekly Sprint — 2026-W34

> 本轮采用 7 天冲刺：2026-08-20 ～ 2026-08-26。

## 本周唯一核心结果

> 把小红书虚拟产品工作台 V1 收口到 **Business-Ready**，并至少跑通 1 次真实端到端 UAT。

## 本周 5 个里程碑

- [ ] M1：百炼文本真实分析严格校验通过，并能写入 Opportunity；
- [ ] M2：真机商品 2/2 深度证据验证通过；
- [ ] M3：同一真实账号完成榜单 → 店铺 → 笔记 → 分析 → Opportunity；
- [ ] M4：真实 Opportunity → 产品 → 内容 → 图片 → 视觉建议 → 人工审核；
- [ ] M5：成功导出 ZIP，并再跑一次确认闭环可重复。

## 本周成功标准

成功不是“代码又多了很多”。

本周算成功，只要：

1. 至少关闭当前真实闭环的核心阻塞；
2. 不继续扩 V1 范围；
3. 有一条真实证据链从前端一直跑到 ZIP；
4. 用户能通过正常工作台流程使用，而不是依赖手工补状态；
5. 到周末能明确说“现在可以开始第一轮真实业务实验”。

## 本周失败的典型形式

- 又新增很多“以后可能有用”的功能；
- 重做 UI，但真实闭环仍没通；
- 测试文件全绿，却没有真实 live E2E；
- 为了自动发布 / 矩阵 / Obsidian 又重构系统；
- 一边修工作台一边提前做正式选品，导致技术问题和业务问题混在一起；
- 每天都在改代码，但说不清到底少了哪个阻塞。

## 本周明确不做

- 正式第一轮选品业务实验；
- 多账号矩阵；
- 自动发布；
- PersonalOS 软件化；
- 大规模新增 Skill / Agent；
- 与 Business-Ready 无关的 UI 重做；
- 7×24 小时 release 稳定性验证；
- 新项目启动。

## Business-Ready 之后怎么办

一旦本周提前达到 Business-Ready，不继续美化工作台。

下一轮冲刺立即切换为：

> **小红书虚拟产品第一轮真实业务实验：候选 → 看品 → 商业假设 → MVP → 内容测试 → 人工发布 → 真实反馈。**
