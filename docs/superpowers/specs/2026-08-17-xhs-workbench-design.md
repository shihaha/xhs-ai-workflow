# 小红书需求雷达与内容工作台设计

权威需求文件为仓库根目录的 `SYSTEM_SPEC_AND_ACCEPTANCE.md`。

系统采用本地浏览器访问的前后端分离结构：React 只读取 FastAPI API；FastAPI 负责业务规则、任务状态与适配器调度；SQLite 保存事实状态；运行目录保存日志、截图、原始响应和导出包。第三方仓库不能直接写业务表，只能返回统一 DTO，由应用服务校验后入库。

任务执行采用数据库租约和显式状态机。V1 使用单进程后台 worker，避免引入 Redis；进程重启会回收过期租约并要求人工确认。外部依赖均有 health probe，UI 不推测其状态。

开发按可运行纵切面推进：先完成任务、证据和真实状态 UI，再接入榜单/网页采集、安卓设备、AI 分析，最后接入产品与内容链路。每个纵切面都从空数据库验证，不加载演示业务数据。
