大家好，我是南墙，03 年、25 年毕业，大学期间做了不少项目，大二开过公司，一直没上过班，目前是自由职业。

过去 90 天，我在本地用掉了 406.11 亿 Token。总排行榜里排第 73，惠州地区第 1。

现在主要做小红书虚拟产品这一块，从找需求、做产品到内容获客，整套流程已经用 AI 串了起来。AI 主要处理重复的采集、整理、分析和执行，我负责选方向、定产品和最后验收。

前前后后我一共做了 26 个虚拟产品，每个月大概能给我带来 1～2w 左右的被动收入。结果还不算大，有些环节也还需要人工处理，但整套流程已经可以稳定跑起来了。

## 一、项目经历

作者回顾了大学阶段从招生、人力中介、校园业务、公司主体、自媒体账号、公众号矩阵、社群、To G 招商等项目经历。核心转变是逐渐意识到：如果项目的关键结果不掌握在自己手里，长期积累会很弱；因此后来把更多精力转到自己可控的互联网产品。

2024 年后，作者开始把手里的小红书账号用于开店卖虚拟产品。这一块持续到 2026 年，期间经历产品下架、店铺封禁、平台政策变化、同行举报等问题。到了 2026 年，作者尝试用 AI 把“找需求、做产品、发内容、卖产品”串起来。

## 二、项目接连失败后的心态变化

作者提到，虽然 2023 年通过人力和其他业务赚到过钱，但多个项目停摆以及 To G 项目长期无法落地，使他开始重新思考“什么是真正掌握在自己手里的能力和资产”。最终把资源中介类业务逐渐放下，转向可积累的互联网项目。

## 三、从需求到获客，AI 一条龙

### 找需求——AI自动跑，人做选择题

真要让 AI 自己把产品卖出去，得先解决一个问题：市场上什么东西有人买。

作者以前靠人工刷小红书，看数据好的笔记、账号主页、卖什么、价格多少。但人工覆盖面有限。后来改用小红书千帆数据中心：每天更新阅读榜、引流榜、热卖榜、成交榜，且每个榜又分优秀内容和优秀账号，一共 8 个入口。

作者让 AI 自动扫这些榜单，一轮覆盖几百条数据。榜单数据进来之后，AI 会先给账号评分。成交金额和支付转化率权重最高，阅读量只占较小部分；连续多天上榜、同时进入多个榜单、低粉已有成交都会获得额外加分。

筛完之后，AI 控制手机逐个打开高分账号的小红书店铺，把商品分享链接复制出来，再交给电脑采集详情和图片。每个账号采完以后要核对数量，手机拿到多少个唯一商品链接，本地就要有多少份商品详情；数量对不上不进入分析。

数据拿全后，AI 分析每个账号卖什么品类、定价、销量最高商品、粉丝量、是否低粉高销。最后把品类和产品形态相近的账号放到一起，根据账号数、商品数、价格区间、最高可见销量和商品图证据，给出当前市场状态、结论和下一步动作。版权、平台规则、交付问题也根据真实证据写进结论。

AI 负责采集、评分、分析和合并，人直接看结果。具体要不要跟进、做成什么产品，最后由人决定。

### 做产品——人定方向，AI做执行

从看板上挑出一个方向时，这个方向的数据已经存在：什么产品在卖、什么价格、主图和详情页什么样，本地都有，不需要再从头搜。

接下来先由人决定产品形态。同样的需求可以走不同的制作路线。

如果是虚拟资料——模板、教程、素材包等，前面采到的商品信息和图片可以判断同行卖什么、怎样展示；但商品详情页看不到付款后具体交付什么，所以还需要去闲鱼、淘宝、拼多多购买几份同方向成品资料。这一步需要人付款，AI 无法代替。

资料买回来以后，再和 AI 一起分析内容、确定产品结构，按模块做出自己的版本：

```text
对标店铺的商品信息和图片
+ 闲鱼买的资料
+ 淘宝买的资料
+ 拼多多买的资料
        ↓
AI分析资料
        ↓
人确定结构
        ↓
按模块制作
```

这些资料用于理解同类产品通常包含什么、哪些问题没有解决。具体内容要重新整理，不能把几份资料直接拼接。

如果是 APP、网站、小程序，则把需求资料交给 Codex。先让 Codex 画图片原型，人确认功能和视觉以后，再按原型还原 UI、开发逻辑，并逐步截图检查。

虚拟资料还是 APP/网站/小程序，必须由人判断。AI 把市场证据和对标数据摆出来，但做成什么形态、怎么差异化、怎么定价，仍需要人的市场判断。

### 做内容——AI跑日常，人定调

产品做出来以后，内容走标准化流水线。

第一步，AI 把产品资料理清楚：卖给谁、解决什么问题、在什么场景用。然后定核心关键词，所有内容围绕这些词布局。

关键词定好后，AI 采集这些词下排名靠前的对标笔记。图文保存正文和全部图片；视频保存原视频、关键帧和语音稿。作者当前主要做图文，所以后面的单篇拆解和模板聚类只继续处理图文，视频完整保留在对标页。

拆到一定量后，AI 把结构相似的笔记归到一起，提炼模板草案。草案出来后，人需要参与判断：哪些结构真的有效、哪些细节要调。确认以后，再把草案做成可以直接执行的内容 Skill。

Skill 做好以后，每天到点 AI 按规则生成笔记草稿，再由 AI 自己审一轮——检查事实、图片排版、是否偏离 Skill。审不过返工。新的 Skill 刚开始跑时保持人工审核，人发现问题就继续调整 Skill。稳定以后，可以减少人工检查。

## 四、这套流程是怎么搭起来的

作者认为完整环境并不复杂：一台电脑、Obsidian、一台登录小红书的安卓手机、一个能读取本地文件、运行脚本和调用工具的 AI；找需求还要能进入千帆数据中心。

AI 可以用 Claude Code、Codex、Hermes、OpenClaw 等，只要能把本地文件、脚本和工具接起来。作者提到较舒服的方式是让 Codex 去指挥 Claude Code 跑流程，人只关注结果。

### 4.1 找需求：从榜单里筛出值得做的方向

找需求由一个主 Agent 和两个子 Agent 配合完成：

- 千帆采集子 Agent：拿全当天榜单；
- 账号分析子 Agent：逐个查看账号商品和图片；
- 主 Agent：账号评分、商品采集、完整性核对、跨账号汇总。

完整流程：

```text
千帆采集子 Agent 拿全 8 个榜单入口
  ↓
主 Agent 给榜单账号评分
  ↓
主 Agent 控制手机进入高分账号店铺
  ↓
手机拿短链，电脑采集全部商品
  ↓
主 Agent 核对商品和图片是否完整
  ↓
账号分析子 Agent 逐号分析
  ↓
主 Agent 合并多个账号中重复出现的产品方向
  ↓
同步 Obsidian，由人决定是否继续做
```

#### 正式开始前先确认四件事

- 小红书账号能正常进入千帆数据中心；
- 浏览器已登录千帆和小红书；
- 安卓手机已登录小红书，主 Agent 可以正常操作；
- Obsidian 工作台可以正常打开和保存数据。

浏览器最好使用单独采集空间，第一次登录后持续使用同一个空间。第一次运行先测试一个商品较少账号，确认主页、店铺、复制商品链接、返回等动作正常，再批量跑。

#### 第一步，采集千帆的 8 个榜单入口

采集四类榜单：

- 阅读榜：看哪些内容正在拿流量；
- 引流榜：看哪些内容能把人带进商品页；
- 热卖榜：看哪些商品正在起量；
- 成交榜：看哪些账号产生真实交易。

每类又分优秀内容和优秀账号，共 8 个入口。

千帆采集子 Agent 依次打开 8 个入口，每个入口最多 20 页。每翻一页随机等待 60～90 秒，并检查排名连续性。中间缺排名、重复、榜单与当前页面对不上，就重做当前页。8 个入口全部完成后才进入账号筛选。

榜单事实保留来源榜单、排名、笔记标题、账号名称、阅读量区间、商品点击率区间、支付转化率区间、成交金额区间、笔记和账号唯一标识。此阶段不根据标题猜品类。

#### 第二步，算出哪些账号值得进店深挖

账号总分：

```text
账号总分 = 需求证据分 × 可信度加成 × 低粉加成
```

需求证据分：

```text
需求证据分 = 成交分 × 50% + 支付转化分 × 35% + 阅读分 × 15%
```

成交金额权重最高，支付转化其次，阅读量最低，目的是更靠近真实付费需求。

可信度加成：

```text
跨天分 = 上榜天数 ÷ 10，最高记 1
跨榜分 = 进入的榜单类型数 ÷ 4，最高记 1
可信度加成 = 1 + 跨天分 × 25% + 跨榜分 × 25%
```

低粉加成：

```text
低粉加成 = 1 +（1000 - 粉丝数）÷ 1000 × 0.6
```

仅在粉丝少于 1000 时生效。

所有账号算完后按总分降序，默认先取前 20 个深挖。评分只决定“先看谁”，具体卖什么、靠哪款商品成交、交付复杂不复杂，仍要真实进店。

#### 第三步，让主 Agent 控制手机进入账号店铺

千帆能看哪些账号有成交，但没有完整商品列表，所以要进入小红书店铺。

电脑端难以稳定从账号主页进入店铺并遍历商品，因此主 Agent 把账号主页交给手机小红书 App 打开，从主页进入店铺，逐个商品复制分享链接；电脑拿到具体商品链接后再采详情和图片。

榜单返回 userId，可拼成：

```text
https://www.xiaohongshu.com/user/profile/<userId>
```

再通过 ADB 交给手机：

```text
adb shell am start -a android.intent.action.VIEW \
  -d "https://www.xiaohongshu.com/user/profile/<userId>"
```

手机流程：

```text
打开账号主页
  ↓
找到并进入店铺
  ↓
逐个打开商品
  ↓
复制商品分享链接
  ↓
返回店铺继续下一个
  ↓
向下滑动，直到全部商品处理完成
```

每完成动作先确认手机进入正确页面。锁屏、卡住、分享面板没开、返回跑偏时先恢复；多次恢复失败就停止当前账号，避免后续点击继续跑偏。

#### 第四步，把每个商品的详情和图片拿全

手机拿到分享短链后，电脑逐条打开商品页，保存：

- 原链接；
- 标题、价格、可见销量；
- 规格和详情文字；
- 页面全部图片。

每个账号单独文件夹，每个商品再单独分开。这样账号分析子 Agent 一次只看当前账号。

#### 第五步，先对数量，再开始分析

先核对：

```text
手机拿到的唯一商品链接数 = 本地成功保存的商品详情数
```

商品数量对齐后，再检查图片数量和文件是否能正常打开。数量和图片没有对齐之前不进入分析。缺什么补什么；无法补齐的账号退出当天汇总，但已采内容继续保留用于排查。

#### 第六步，每个账号单独分析

每个账号独立调用账号分析子 Agent，整理：

- 账号主要卖什么；
- 商品总数；
- 价格区间；
- 销量最高商品；
- 产品形态（资料、模板、测试、教程等）；
- 用户购买后拿到什么、交付复杂度；
- 是否低粉高销。

商品图必须逐张查看。很多虚拟产品不会在标题写清具体内容，目录、测试结果、使用流程、套餐差别往往都在图中。每条图片结论要标对应账号、商品、图片。商品和图片没有看完，账号不进入最终汇总。

#### 第七步，找出多个账号都在卖的方向

单个账号只能说明有人做，多个账号都卖相近产品，市场证据才变强。

主 Agent 读取全部账号画像，把主要品类和产品形态相近的账号归在一起。每个方向写清：

- 多少账号在卖、总商品数；
- 价格区间、最高可见销量；
- 商品图展示什么、买完拿到什么；
- 结合低粉高销、交付方式、制作门槛给当前结论和下一步动作；
- 若有版权、平台规则、交付问题，也写入结论。

状态包括：观察中、升温、已验证、降温、放弃。这些状态只说明证据支持什么，是否做、做成什么、投入多少仍由人决定。

#### 第八步，在 Obsidian 中查看和选择方向

当天分析后，主 Agent 把需求方向同步到 Obsidian。面板展示：当天完成账号/商品数、最终产品方向、支撑账号和商品、价格范围和最高销量、市场状态、下一步判断。

自动采集和分析随新数据更新，人工判断、计划和验证结果继续保留。

选定方向后，找需求阶段结束，下一步是把它做成能够正常交付的产品。

### 4.2 做产品：从需求到可交付的产品

前面选中的产品方向已经保存在本地。对标账号卖什么、价格、哪些商品有销量、商品图怎么介绍，都可以用于判断市场需求和产品形态。

#### 虚拟资料

商品详情页只能看到产品怎么卖，看不到付款后到底交付什么。确定要做模板、教程、素材包以后，还要去闲鱼、淘宝、拼多多购买几份同方向成品资料。

把前面采集的需求资料、对标商品和新买的文件交给 AI，让它逐份读取。

第一轮先整理资料：每份讲什么、适合谁、怎么交付，找重复内容、独有内容、没有解决的问题。然后**人参与判断**，确定产品做给谁、解决哪个问题、做成模板还是教程、交付包含哪些文件。

这些问题聊清楚以后，再一起定产品目录。AI 可以先出一个版本，人继续删、改顺序、补关键内容，直到每一部分解决什么问题都清楚。

目录定下后，按模块制作。AI 每完成一部分，人就看一部分。检查是否照搬、是否有拼接感、事实是否准确、能否直接使用。最后统一整理文件、目录和排版，并实际打开检查错位、链接、文件齐全度和用户是否知道怎么开始。

#### 网站、小程序和本地工具

网站、小程序、本地工具可以交给 Codex 开发，先从图片原型开始。将需求资料交给 Codex，让它分析目标用户、核心需求、使用场景、核心页面，然后调用图片生成工具制作高保真 UI 原型。

原文示例提示：

```text
请完整读取这个产品方向的需求资料，整理出目标用户、核心需求、
主要使用场景，以及完成核心功能需要哪些页面。

调用内置图片生成工具，为这个产品制作高保真的 UI 图片原型。
每个核心页面和关键状态分别出图，页面中使用接近真实产品的内容，
画面要完整展示布局、颜色、字号、间距、按钮和信息层级。

这一阶段只生成图片，不写 UI 代码，也不开发功能。
出图后等我逐张确认，并根据我的反馈继续修改图片。
```

图片原型没有调满意，不进入下一步。图片确认后，让 Codex 按原型 1:1 写 UI，先还原页面、暂不接业务逻辑。每完成一个页面，运行实际界面并截图，与原型对比布局、文字、颜色、字号、间距、图片，有差异继续改。

所有页面还原后，再开发具体逻辑。逻辑完成后让 Codex 按真实用户方式从头操作，每完成一个动作都截图检查当前视觉、内容和状态，通过再继续下一步。

对不懂编程的人来说，验收看两件事：实际页面是否与原型一致，产品功能是否能正常使用。两项都确认后才算开发完成。

产品开发完成后，下一步才围绕它做内容。

### 4.3 发内容获客：从产品资料到持续产出内容

产品做完以后，内容获客不能直接让 AI 随便写几篇。必须先弄清楚产品，再找对标、拆对标、做模板，最后稳定产出。

完整顺序：

```text
产品资料 → 产品分析子 Agent → 关键词布局子 Agent → 手机采短链 → 电脑入库
                                                   ├─ 图文 → 单篇拆解 → 聚类出模板草案
                                                   └─ 视频 → 原视频 + 关键帧 + 语音稿 → 当前留在对标页
模板草案 → 人和 AI 一起做成内容 Skill → 日更生成子 Agent → 内容审查子 Agent
```

#### 第一步，先让产品分析子 Agent 吃透产品

把产品介绍、价格、购买方式、页面截图、使用说明、客户反馈、FAQ、以前文案等原始材料都放进去，不需要提前压缩。

产品分析子 Agent 保留原始文件，再按产品形态整理，产出产品总览和资料索引。后面的关键词、模板和日更内容都从这里拿事实。

这一轮需要人检查价格、功能、适用范围、效果、购买方式、案例、评价。只要产品是什么、给谁用、解决什么问题没有说清，就先补资料。

#### 第二步，让关键词布局子 Agent 决定去搜什么

从品类、人群、痛点、场景、卖点、购买顾虑、替代方案里整理出 10～20 个研究关键词。

这些词用于找对标，不是发布时的话题。只搜产品名会太单一，要加入人群、场景和问题。

关键词出来后，在 Obsidian 设置每个词采几篇、是否 A-Z 扩展、是否采评论。第一次每个词先 5～10 篇，方向对了再加。A-Z 扩展会变成 26 个实际搜索词，只建议给少量短核心词开启。

手机在小红书 App 搜关键词、打开笔记并复制短链，电脑接手标题、正文、话题、作者、互动数据和实际搜索词。图文下载封面和全部内页；视频下载原视频和封面、抽关键帧、用本地语音模型转写时间轴语音稿。

第一次先采 2 篇测试，确认图文标题/正文/封面/内页顺序，视频原视频/封面/关键帧/语音稿，以及互动数据都正常，再批量跑。中途断开或掉线，已完成内容保留，恢复后继续。

#### 第三步，单篇拆解，再聚类出模板草案

图文逐篇调用单篇拆解子 Agent。一个 Agent 只看一篇，拆标题公式、正文结构、封面与内页分工、开头钩子、互动数据，再写回原笔记。

必须一篇一篇拆，避免把多篇的标题、正文、图片混在一起。标题要拆到可复用公式，例如“人群＋具体问题＋结果”“场景＋数量＋解决方案”。互动数据和内容一起看，不需要强行总结爆款原因。

一批对标拆完后再调用模板聚类子 Agent。它主要拿前面的结构化拆解结果比较。内容角度、标题结构、正文骨架接近的归一组。至少 3 篇对标支撑才能生成模板草案，只有 1～2 篇就继续采。

#### 第四步，把模板草案做成可以执行的 Skill

聚类 Agent 最后生成 `模板说明.md`，记录标题公式、正文结构、话题策略、互动点、配图方式，但这还是研究结论。

真正进入生产的是同目录的 `SKILL.md`。Skill 要明确：读哪些产品资料、按什么顺序做、最后交付什么。

产品资料必须写准，每条事实都指向实际文件，不能让新 Agent 自己在几个产品间猜。文案要写到具体动作：标题公式、正文几段、每段解决什么、话题怎么选、哪些说法禁止。图片也要明确封面、内页各自承担什么信息、用产品截图还是重排版、用哪个图片 Skill/脚本、格式和顺序。

人负责确认内容方向和视觉效果，AI 把这些判断整理成可以重复执行的 Skill。Skill 做好后先生成 1 个完整内容包，打开每张图检查。连续问题改 Skill，单篇问题改当前内容。

#### 第五步，日更 Agent 按 Skill 生成，再交给审查 Agent

Skill 测试通过后，在工作台设置每天生成数量。新 Skill 先每天 1 篇，不用的设 0。

主 Agent 每次看当天还缺几篇，只补缺口。上次停在生成、审查或返工，下一次从原位置继续，不重新生成一批。

日更生成子 Agent 一次只处理一个产品和一份 Skill，先读产品总览和资料索引，再读 Skill 指定的产品文件，生成标题、正文、话题、封面和全部内页图，组成完整内容包。

生成后主 Agent 再叫一个新的内容审查子 Agent。它重新读取产品资料和同一份 Skill，再检查文案和每张图片：产品事实是否错、标题/正文是否按 Skill、图片文字是否清楚、标注是否正确。

审查不过就退回生成 Agent 修改，修改后重新审。生成与审查分开，避免同一个 Agent 自己写完自己判通过。

新的 Skill 刚开始跑时可以开人工审核。连续几篇稳定后再减少人工检查。先手动跑几次确认中断恢复、数量不重复、文案图片正常进入 Obsidian，再接定时任务。
